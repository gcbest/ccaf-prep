Explicitly out of scope — don't spend time here

Fine-tuning and training custom models · API authentication and billing · language/framework implementation details · MCP server hosting and infrastructure · Claude's internal architecture and training · embedding models and vector databases · computer use · vision and image analysis · streaming API / SSE · rate limiting and pricing · OAuth and API key rotation · cloud provider specifics · benchmarking · prompt caching internals · tokenization details.

Bedrock and Vertex still matter — not as infrastructure, but as the access layer. Know what changes (auth, client shape, model-ID syntax, regional availability) and what doesn't (prompting, tool design, RAG, evals, orchestration).
Answering strategy
  • "Most effective first step" means cheapest high-leverage fix. Expanding a tool description beats building a routing classifier.
  • Deterministic beats probabilistic when money, safety or compliance is involved. A hook or programmatic gate outranks a prompt instruction.
  • Blame the layer the evidence points at. If the coordinator's logs show a narrow decomposition, the subagents aren't the problem.
  • Over-engineering is usually the wrong answer. Training a classifier, adding a model tier, or consolidating tools are rarely the first step.
  • Least privilege wins — a scoped tool for the common case beats handing over the whole toolset.
